# INTER_WORKER_MESSAGE Contract

## Purpose

Standardize the communication between the workers of the Discovery Orchestrator.

## Format

JSON.

## Required fields

| Field | Type | Description |
|-------|------|-------------|
| `message_version` | string | `"1.0.0"` |
| `from_worker` | string | Emitting worker. |
| `to_worker` | string | Receiving worker. |
| `generated_at` | ISO 8601 | Timestamp. |
| `payload_type` | string | `"discovery_input"`, `"partial_output"`, `"invalidation_request"`, etc. |
| `payload` | object | Message-specific content. |
| `provenance` | object | `source_files`, `source_sessions`, `confidence`. |

## Note on `provenance`

`provenance` is **mandatory in output messages between workers** (`partial_output`, KB entries and derivatives), because the KB requires provenance traceability. In contrast, in the input message `discovery_input` (generated by `init_worker` towards the other workers) `provenance` **does not apply / is optional**: that message does not report findings but execution parameters, so it may be omitted.

## Examples

### `discovery_input` (input, provenance optional)

```json
{
  "message_version": "1.0.0",
  "from_worker": "init_worker",
  "to_worker": "stack_worker",
  "generated_at": "2026-07-21T05:00:00Z",
  "payload_type": "discovery_input",
  "payload": {
    "project_root": "/home/user/project",
    "scope": "stack",
    "previous_kb_entries": ["stack.md", "dependencies.md"]
  }
}
```

### `partial_output` (output, provenance mandatory)

```json
{
  "message_version": "1.0.0",
  "from_worker": "stack_worker",
  "to_worker": "framework_worker",
  "generated_at": "2026-07-21T05:00:00Z",
  "payload_type": "partial_output",
  "payload": {
    "languages": ["Python"],
    "frameworks": ["Flask"],
    "config_files": ["src/app.py"]
  },
  "provenance": {
    "source_files": ["src/app.py", "requirements.txt"],
    "source_sessions": [],
    "confidence": "high"
  }
}
```

### `invalidation_request`

```json
{
  "message_version": "1.0.0",
  "from_worker": "init_worker",
  "to_worker": "patterns_worker",
  "generated_at": "2026-07-21T05:00:00Z",
  "payload_type": "invalidation_request",
  "payload": {
    "invalidated_entries": ["development_patterns.md"],
    "reason": "config_files_hash changed"
  }
}
```
